## Mixed-Harness runtime defects found and fixed

The failed Runs were retained as audit evidence; none was rewritten or treated
as a successful business route.

1. r1/r2 showed that a process-wide tmux server can retain the environment of
   the process that first created it. Later Runs inherited a stale Claude
   endpoint/model despite current shell configuration. The runtime now uses a
   deterministic per-Run tmux server label, and a live isolation smoke test
   proved that a new Run receives the current environment.
2. r3 proved that Claude Code could execute the full Developer turn but its
   `acceptEdits` mode denied ordinary Bash validation and the formal
   `agent-team handoff`. The Claude Launch Profile now runs ordinary Bash in
   the OS sandbox, exactly allows the three formal role actions, explicitly
   denies management actions, disables the unsandboxed escape hatch and grants
   only Claude's own internal temporary CWD path beyond the workspace.
3. r5 independently reproduced the P3 but blocked while staging the
   Reviewer→Developer Handoff: target-profile validation invoked
   `claude --version` inside the Codex sandbox, and Claude tried to write
   `~/.claude/debug`. The non-authenticating version probe now uses a private
   short-lived `CLAUDE_CONFIG_DIR`. A real macOS Seatbelt test proved the
   unisolated probe fails, the isolated probe returns version 2.1.25, and the
   temporary directory is removed.

## Legacy failed Run handling

- two legacy audit files were tightened to mode `0600`; their SHA-256 values were
  unchanged.
