`deepseek-official/doubao-seed-2-0-pro-260215` with the temporary validated DSH

## Initial role

`developer`.

## Collaboration protocol

Developer → Reviewer. Reviewer findings → Developer → Reviewer. A clean
Reviewer and independently passing package/load gate → fresh Validator.
Validator findings → Developer → Reviewer → a later fresh Validator. Each
Validator route freezes a new immutable Plugin/Profile generation and
preserves earlier generations. Source defects in a frozen generation are
normal findings and do not Block.

Every route is selected by the active role and committed through the formal
CLI. The Agent-Team Skill is guidance only and has no terminal arguments.
Every External Turn ends with exactly one `$AGENT_TEAM_CLI handoff`,
`complete`, or `block` command and stops business work afterward. Roles must
continue their own in-scope build, test, package, and repair work rather than
asking the Origin to perform it.

## Completion condition

Validator may complete only after independently verifying: a clean Reviewer
verdict; packed-artifact contents, archive-only isolated install, activation,
and real Loader smoke; a complete from-zero package diff; frozen Agent-Team
installation and real DSH loading; direct calls to both tools; correct schema
and typed/bounded query output; denial/path attacks with unchanged database
hash and rows; cancellation/deadline/lifecycle behavior; valid package,
bundle, generated and bilingual documentation surfaces; exact selected model
and `256000/131072` request evidence; durable traces; applicable tests/gates;
and no remaining P0-P3 finding.

## Final delivery

Return a Completion Package through this Codex Origin containing initial-empty
evidence, changed files, loop/finding dispositions, exact tests and product
gates, observed model/capacity, frozen generation identities, direct-tool and
private-Profile evidence, denial/immutability proof, trace evidence,
limitations, and final workspace state. The Origin restores the temporary
managed DSH capacity override after terminal completion or cancellation when
safe.

## Session continuity

Developer and Reviewer use distinct `resume` Sessions so implementation and
review context survives later Turns. Validator uses `fresh`; every activation
is independent and receives a newly frozen Plugin generation. Codex Origin is
control-plane only.

When DSH structurally reports an explicit output-budget stop for Developer or
Reviewer, Agent-Team may create a new counted Turn for that same role and
available preserved Session only before any Block and only after every runtime
safety gate passes. The automatic input identifies the previous Turn and asks
the role to inspect the live worktree and continue the unfinished
responsibility. It grants no new authority and is not a Block Resume. A fresh
Validator, ordinary crashes, permissions, truncated audit, existing Outboxes,
exhausted limits, stale/unavailable Sessions, or two consecutive Git-visible
no-progress output-limited Turns must Block.

## Shared context policy

Every role receives the immutable Request, Protocol, current frozen
`input.md`, and independent Facts paths. Kickoff, Handoff, and Resume payloads
are frozen as the next Turn input. Roles verify the clean worktree directly.
No role may inspect prior candidates, Run state outside its supplied facts,
other DSH worktrees, or prior generation Homes; Validator may inspect only its
current managed Profile and Agent-Team-provided generation identity.

## Observability policy

Use Full Audit because every business role is External and Origin is
control-plane only. Retain redacted raw data with standard redaction and a
64 MiB per-Turn limit. Every formal payload contains concrete non-empty
`## Decision rationale` and `## Evidence` sections. Capture Harness-exposed
summaries and events only, never private hidden chain-of-thought.

## Block and resume policy

Every committed Block returns to the user. Origin may perform read-only
diagnosis or deterministic recovery but may not auto-Resume. Only a new
explicit user instruction may Resume. Source, test, package, isolated-install,
activation, and Loader findings follow the Developer/Reviewer loop and are not
Blocks. A pre-Block Automatic Continuation is normal routing and needs no
Origin action, but cannot occur after any Block. Immutable model, workspace,
Profile, role, launch mode, or limit changes require Cancel plus a new Run.
